# 大模型文本水印技术原理：KGW、SynthID-Text 与 Claude

## 问题定义

生成式文本水印的目标不是寻找 AI 文本自然形成的文风，而是在 next-token 采样过程中主动建立一个与密钥相关的统计信号。给定前文 $x_{<t}$，语言模型先产生下一个 token 的概率分布：

$$p_t(v)=P(x_t=v\mid x_{<t})$$

水印系统随后使用密钥 $K$、前文和某种采样规则选择 $x_t$。重复多次后，单步不可察觉的选择累积成统计证据。检测端重新分词并使用同一密钥计算分数，再将分数与零假设下的分布或校准阈值比较。

一套生成式水印可以拆成三个组件：

1. **随机种子生成器**：根据密钥和近期上下文产生每一步的伪随机种子
2. **采样算法**：利用种子从模型分布中选取 token，并建立“种子与输出 token”的相关性
3. **评分与判定机制**：根据待测 token 序列和密钥累计相关性证据

这一区分很重要：KGW 与 SynthID-Text 都属于同一框架，但主要差异发生在采样算法和评分方式，而不是“一个使用统计、另一个不使用统计”。

## KGW：Soft Red List 与 logit bias

Kirchenbauer 等人在 2023 年提出的经典方案通常简称 KGW。其核心是根据密钥和前文，为每一个生成位置动态划分词表。

### 嵌入过程

1. 用密钥和前文 token 的哈希产生伪随机种子
2. 将词表划分为绿名单 $G_t$ 与红名单 $R_t$
3. 对绿名单 token 的 logits 增加偏置 $\delta$：

$$\tilde l_t(v)=l_t(v)+\delta\cdot \mathbf 1[v\in G_t]$$

4. 从修改后的分布 $\operatorname{softmax}(\tilde l_t)$ 采样

绿名单随前文变化，读者无法仅凭某个词判断是否带水印；真正的信号是整段文本对一系列动态绿名单的命中率偏高。

### 检测过程

检测器使用同一密钥重建每一步的绿名单。若共有 $T$ 个可计分 token，其中 $N_G$ 个落入绿名单，且零假设下绿名单比例为 $\gamma$，可构造近似 z 分数：

$$z=\frac{N_G-\gamma T}{\sqrt{T\gamma(1-\gamma)}}$$

分数越高，文本与该密钥控制的生成过程越一致。实际实现还需处理重复上下文、短文本、分词差异和阈值校准，不能只凭“超过 50%”作判断。

### KGW 的工程权衡

- $\delta$ 越大，检测信号通常越强，但对原始 next-token 分布的改动也越大
- 文本越长、模型分布熵越高，通常越容易积累信号
- 低温生成、事实答案、代码和固定格式输出的选择空间较小，水印更弱
- 截取、少量修改可能保留信号；充分改写、翻译或混合文本会削弱相关性
- 方案简单直观，但“检测率、输出质量和抗修改性”之间的权衡较直接

## SynthID-Text：Tournament sampling

Google DeepMind 在 2024 年发表的 SynthID-Text 仍然使用“密钥 + 前文”产生伪随机信号，但用 Tournament sampling 取代简单的绿名单 logit bias，并提供更完整的生产化设计。

### 论文公开的生成机制

在论文实验中，种子由水印密钥与最近若干 token 的滑动窗口哈希生成。该种子输入多个伪随机水印函数 $g_1,\ldots,g_m$，它们给候选 token 分配水印分数。

Tournament sampling 的直观流程是：

1. 从原始模型分布 $p_t$ 抽取一组候选 token；候选可以重复
2. 将候选两两配对
3. 第一层使用 $g_1$ 选择每对中水印分数较高者
4. 胜者继续配对，后续各层依次使用 $g_2,\ldots,g_m$
5. 最终胜出的 token 成为输出

因此，水印不是先确定一个“唯一最佳词”再换成同义词，而是在模型原本允许的概率分布内组织随机选择，使输出 token 与密钥生成的水印函数持续形成相关性。

### 检测机制

论文给出的基础评分会计算实际 token 在各水印函数下的平均分：

$$\operatorname{Score}(x)=\frac{1}{mT}\sum_{t=1}^{T}\sum_{\ell=1}^{m}g_\ell(x_t,r_t)$$

Tournament sampling 倾向选择高分 token，因此带水印文本的聚合分数通常高于未加水印文本。论文还研究了其他评分函数、选择性判定和针对 speculative sampling 的学习式 Bayesian scorer；所以 SynthID-Text 不能被简化为 KGW 式“统计绿词并做 z 检验”。

### non-distortionary 的准确含义

SynthID-Text 可配置为 non-distortionary 或 distortionary：

- **non-distortionary 配置**：按论文定义，在指定的随机种子平均或序列级条件下保持原始模型分布；目标是保存质量，同时仍在单次生成与密钥之间建立可检测相关性
- **distortionary 配置**：允许更明显地改变分布，以更强检测率换取一定质量或多样性损失

“non-distortionary”不表示同一 prompt 下逐字输出不变。水印仍会影响一次具体生成采用哪个 token；它表示从规定的概率分布层面看，不系统性偏爱某些固定词，或在更强定义下保持序列分布。

论文的 Gemini 线上实验覆盖接近 2,000 万条回答，点赞与点踩率未出现统计显著差异；受控人工评价、perplexity 和标准能力评测也未发现显著质量下降。但实验同时指出，non-distortionary 配置仍可能降低不同回答之间的多样性。

### 生产化设计

SynthID-Text 只修改采样层，不要求重训模型；检测也不需要调用底层 LLM。论文还给出了与 speculative sampling 结合的两种策略，在检测强度与推理加速效率之间取舍。其额外延迟相对模型前向计算很小，这些特征使它比早期方案更适合大规模在线服务。

## Claude 采用了什么

Anthropic 在 2026-08-14 确认，未来 Claude 模型将使用 **SynthID-Text 的一个版本**。官方已确认的行为边界包括：

- 不添加隐藏字符或额外 token
- 不携带用户、组织、账号、会话或聊天身份信息
- 只在多个候选都足够合理的低风险选择中利用水印随机性
- 不会为了水印强行选择模型原本几乎不会使用的词
- 速度影响可忽略，服务与使用成本不因额外 token 增加
- 检测结果表达 Claude 曾参与生成或处理的可能性，而非作者身份或完整来源证明

Anthropic 尚未公开 Claude 变体的以下参数：

- 上下文窗口、种子生成器和重复上下文处理方式
- Tournament sampling 的层数、配置及其相对论文方案的改动
- 采用 non-distortionary 还是其他具体配置
- 检测统计量、校准方法、阈值、最低推荐长度与误报率
- 各语言及截取、拼接、翻译、改写攻击下的量化结果

因此，可以用 SynthID-Text 论文解释 Claude 的技术家族和设计原则，但不能把论文实验中的窗口长度、tournament 参数或评分器直接写成 Claude 的确定实现。

## 三种方案的比较

| 维度 | KGW | SynthID-Text 论文 | Claude 已确认实现 |
|---|---|---|---|
| 水印位置 | next-token 采样层 | next-token 采样层 | next-token 采样层 |
| 主要机制 | 动态绿名单 + logit bias | 密钥化水印函数 + Tournament sampling | SynthID-Text 的一个未完全公开变体 |
| 基础检测 | 绿名单命中统计，常用 z 检验 | 聚合多个水印函数分数，也支持其他/学习式评分 | 将提供检测 API，内部统计量未公开 |
| 是否修改模型参数 | 否 | 否 | 未表示需要修改训练参数，官方描述为生成阶段机制 |
| 分布影响 | 典型配置为 distortionary | 可配置 non-distortionary 或 distortionary | 官方称无实际质量影响，具体配置未知 |
| 生产化能力 | 原理简单，需自行处理推理栈 | 支持 speculative sampling，已在 Gemini 大规模验证 | 声称速度影响可忽略、无额外 token |
| 身份载荷 | 方案可由实现者设计，但经典目标是来源检测 | 论文目标是水印检测 | 明确不含个人、组织、聊天或会话信息 |

## 水印强度由什么决定

比“文本有多少字”更准确的量是：**模型做出了多少个不损害质量、且带有足够熵的可选决策**。

| 场景 | 预期信号 | 主要原因 |
|---|---:|---|
| 长篇解释、描述、创作 | 较强 | 可接受的 token 选择较多 |
| Claude 完成的翻译 | 较强 | 目标语言 token 基本都由模型选择 |
| 事实密集回答 | 较弱 | 专名、数字和事实答案选择空间小 |
| 代码 | 较弱 | 语法、API 和标识符要求精确；注释可能承载信号 |
| 轻度校对 | 很弱 | 大部分 token 来自用户，Claude 只改少量位置 |
| 短文本 | 很弱 | 可累计的独立证据不足 |
| 低温或确定性解码 | 较弱 | 分布熵降低，可供水印利用的随机性减少 |

检测到水印只能支持“该提供方很可能参与过内容生成或处理”。检测不到则可能来自模型未启用水印、文本太短、任务熵太低、后续编辑破坏信号，或内容由其他系统生成。

## 主动水印与被动 AI 检测

被动检测分析 perplexity、句式、词频或分类器特征，寻找模型自然留下的习惯；主动水印寻找生成方有意注入的密钥相关信号。二者都依赖统计推断，但零假设、所需权限和失效方式不同。

主动水印的优势是检测目标明确，不要求“人类文本与 AI 文本天然不同”；局限是必须由生成服务在采样阶段实施，并且无法覆盖未参与该水印体系的模型。被动检测覆盖面更广，却容易发生跨领域失效、模型迭代漂移和群体偏差。实践中二者更适合作为互补信号，而非互相替代。

## Takeaways

1. **统一框架是“密钥化随机种子 + 采样器 + 评分器”**：KGW 与 SynthID-Text 的差别主要在如何利用采样自由度和如何聚合证据。
2. **KGW 用直接的分布偏置换取简单、强信号**；SynthID-Text 通过 Tournament sampling 提供更好的质量、检测与生产部署权衡。
3. **水印容量由条件分布熵决定**：长文本只是常见代理指标，真正关键的是模型有多少个同样合理的 token 可选。
4. **Claude 只确认采用 SynthID-Text 的一个版本**：论文机制可以解释设计原则，但其具体参数、配置和检测器仍未公开。
5. **水印是概率性参与证据，不是数字签名**：它不能证明作者、完整来源或用户身份，也不能以“无水印”证明内容由人类创作。

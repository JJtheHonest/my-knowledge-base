# 大模型文本水印的合规化与技术趋势

## 事件脉络

Anthropic 为履行欧盟《AI 法案》第 50(2) 条及《AI 生成内容透明度行为准则》，宣布未来 Claude 模型将为生成文本提供机器可读标记，并为支持的文件附加 C2PA content credential。

最初公告只说明文本会带有“不可感知的嵌入式水印”，没有公开具体机制。由于“嵌入”容易让人联想到零宽字符、特殊 Unicode 或排版标记，The Register 第一轮评论据此质疑 OCR 和文本重排可轻易去除水印，并用 Apple 的措辞与标点陷阱作对照。

2026-08-14，Anthropic 进一步确认 Claude 使用 Google DeepMind SynthID-Text 的一个版本：水印不添加隐藏字符或额外 token，而是在多个合理 next-token 之间，用密钥与前文控制的随机性留下统计模式。此次澄清改变了争议焦点：问题不再是“隐藏字符能否被 OCR 清除”，而是“统计信号在不同文本类型和后续编辑下有多可靠”。

Anthropic 将对支持的模型在全球启用水印，理由是目前缺少可持久、可靠地按区域限制水印的办法；此前发布的模型则在法律过渡期内逐步加入支持。公司还计划提供文本检测 API。

## 这不是一种单一的“AI 身份证”

当前讨论容易把三种不同目标混为一谈：

| 机制 | 解决的问题 | 主要限制 |
|---|---|---|
| Claude/SynthID 类文本水印 | 某提供方是否可能参与过文本生成或处理 | 概率性、依赖密钥、短文本与重写下较弱 |
| C2PA 文件凭证 | 文件由谁处理、凭证签名是否有效、文件是否发生凭证可感知的篡改 | 元数据可被截图、重存或格式转换剥离 |
| Apple canary trap | 已知接收者中究竟是谁泄露了资料 | 依赖逐人分发唯一副本及接收者不知情 |

Claude 水印明确不包含用户、组织、账号或会话身份，因此不能用于逐人追踪。这是隐私上的优点，也是取证能力上的边界。Apple 的方案恰好相反：它有意把每份副本映射到具体员工，目标是泄密归因，而非公开环境中的 AI 透明度。

## 如何评价 Anthropic 的方案

### 适合的定位：低成本透明度基础设施

将文本水印评价为“不可能被移除，所以可靠”会设定错误标准。自然语言只要经过完整重写，原有 token 级信号就可能被破坏；任何声称不可移除的方案都很难同时保持文本自由编辑能力。

更合理的成功标准是：

- 对未经处理或轻度编辑的较长文本提供可校准的来源信号
- 在低误报率下仍有实用检出率，并允许对证据不足的样本拒绝判断
- 对质量、延迟和成本的影响足够小，可默认部署到大规模服务
- 不编码用户身份，不要求保存全部聊天记录
- 清楚告知“检出”和“未检出”分别能证明什么

按这些标准，SynthID-Text 的生产实验和低额外成本使其具有现实价值。但在 Anthropic 发布具体误报率、最低长度、多语言及编辑攻击数据前，无法判断 Claude 版本的实际效能。

### “半有效”不等于“没有用”

The Register 将方案描述为 semi-effective，这个判断在“无法抵抗完整重写”层面成立。但内容来源系统并不一定要阻止所有有动机的攻击者才有价值。它仍可服务于平台自动标注、内容审核、研究数据清洗、批量滥用调查和普通用户验证。

这类似垃圾邮件检测、C2PA 和恶意软件信誉信号：单个信号都可能绕过，价值来自低成本覆盖和与其他证据结合。真正的问题不是它是否完美，而是误报、漏报、拒判率和可解释边界是否与使用场景匹配。

### “表演性合规”批评有一半成立

Anthropic 明确表示部署动因是 EU AI Act，因此合规显然是直接驱动力。方案无额外 token、速度影响小，也使其成为成本最低的合规路径之一。The Register 据此称其为 performative compliance，并非毫无依据。

但“由监管驱动”不能推出“技术没有实用价值”。监管可能促使原本缺少商业激励的公共基础设施获得部署。更准确的评价是：**该方案首先是一项合规基础设施，其公共价值取决于检测接口、互操作性和实测可靠性，而不是企业动机是否纯粹。**

## 对 The Register 两轮评论的判断

### 第一轮：部分误解已被排除

- **不成立**：OCR 清除隐藏字符。Anthropic 已明确没有隐藏字符，OCR 不是针对该机制的直接移除手段。
- **仍成立**：充分改写、翻译、拼接会破坏 token 与密钥的统计相关性。
- **仍成立**：C2PA 是可剥离的文件元数据，不是不可删除的像素级水印。
- **比较对象不当**：Apple 的措辞陷阱用于逐人泄密归因，Claude 用于提供方参与检测，安全目标不同。

### 第二轮：批评转向真正的技术边界

The Register 第二篇更准确地抓住了水印依赖“非关键选择”的事实：事实回答、精确代码和短文本中的信号会更稀疏；完全重写可以移除水印；部署首先服务于合规。

其文学性批评也有合理部分。在文学写作中，两个近义词未必具有相同风格价值，“不改变含义”不等于“不改变表达”。不过，单次措辞确实会改变，并不意味着总体质量必然下降；Google 的大规模 A/B 实验和受控人评未发现显著质量差异。争议应表述为“平均质量指标能否覆盖文学风格的细粒度损失”，而不是断言水印必然制造拙劣文本。

## 产业趋势

### 1. 从被动猜测转向生成端主动标记

被动 AI 检测器依赖模型自然文风，并可能随模型升级而失效，还存在跨领域和非母语写作者误报问题。生成端水印不需要假设 AI 与人类文本天然不同，而是检查密钥相关信号。未来更可能形成“主动水印负责已接入提供方，被动检测补充未知模型”的组合。

### 2. 来源基础设施将按内容类型分层

纯文本适合统计水印；图片、音视频和可封装文件更适合 C2PA 等签名来源凭证；需要具体责任人归因的内部文档仍会使用序列号或 canary trap。统一称为“水印”会掩盖它们不同的证据强度和威胁模型。

### 3. 检测 API 将成为新的信任中心

Anthropic 的密钥不公开，外部用户将依赖其检测 API。由此产生新的治理问题：

- API 是否返回校准概率、离散标签还是拒判结果
- 外部研究者能否独立验证误报率和跨语言性能
- 密钥轮换后旧内容能否继续检测
- API 是否会记录待检测的敏感文本
- 不同提供方的检测结果能否使用统一格式

水印算法本身可以开放，但生产密钥和最终判定仍可能集中在模型提供方手中。因此，透明度要求最终会扩展到检测服务的审计与互操作性。

### 4. 开放权重模型构成结构性缺口

托管模型提供方控制采样链路，可以默认强制水印；开放权重模型的部署者可以替换或关闭采样器。即使发布开源 SynthID 实现，也无法保证所有自托管实例启用。

这意味着文本水印更容易形成“受监管商业服务的标配”，而不是覆盖所有 AI 文本的全球统一标记。强监管还可能提高部分用户转向开放权重或离线模型的动机，形成合规覆盖与可规避性之间的张力。

### 5. 多提供方并存会推动互操作标准

Claude、Gemini 和其他提供方可能使用不同密钥甚至不同算法。某一家 API 只能回答“是否与我方水印一致”，无法回答“是否由任意 AI 生成”。若缺乏公共发现机制，平台需要逐一调用多个检测器。

长期更可行的方向是：统一的提供方发现、检测结果格式、置信度语义、密钥轮换与版本声明标准，而不是要求所有厂商共享同一个秘密密钥。C2PA 已为文件提供了部分范式，纯文本领域仍缺少同等成熟的跨厂商协议。

## 应重点观察的后续数据

评价 Claude 水印是否从“合规动作”成长为实用基础设施，应关注：

1. 检测 API 的最低文本长度、误报率、检出率和拒判率
2. 中文等非英语文本及不同分词方案下的表现
3. 低温、代码、事实问答、校对和翻译场景的水印密度
4. 截取、拼接、轻度改写、模型改写和跨语言翻译后的鲁棒性
5. 密钥泄露、密钥轮换、伪造水印及检测 API 滥用的防护
6. 多提供方检测结果能否互操作，以及平台如何向用户解释不确定性

## Takeaways

1. **Anthropic 事件标志着文本水印从论文方案进入监管驱动的默认基础设施阶段**，其首要目标是透明度合规，而非不可绕过的数字取证。
2. **The Register 的 OCR 质疑已被官方澄清排除，但改写攻击、短文本和低熵任务的局限仍然成立。**
3. **“半有效”可以具有公共价值**：前提是低成本、低误报、允许拒判，并与 C2PA、被动检测和平台审核组合使用。
4. **下一阶段的核心问题将从嵌入算法转向检测治理**：API 可审计性、隐私、密钥生命周期、置信度解释和跨厂商互操作。
5. **文本水印不会覆盖整个 AI 生态**：托管模型容易强制部署，开放权重与充分改写始终构成结构性逃逸路径。

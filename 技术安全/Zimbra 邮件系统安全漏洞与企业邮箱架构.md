## Zimbra 系统概述

**Zimbra Collaboration Suite (ZCS)** 是企业级开源电子邮件与协作软件，类似于 Microsoft Exchange 或 Google Workspace，主要服务于企业、政府机构和教育单位。

### 主要特点
- **私有化部署**：支持本地机房部署，满足数据隐私和合规需求
- **开源经济**：提供免费开源版和付费商业版（含技术支持）
- **完整协作套件**：邮件、日历、联系人、任务管理、文件共享
- **多端同步**：Web 端、桌面客户端（Outlook/Thunderbird）、移动端

### 主要用户群体
1. **政府与事业单位**：对数据主权有严格要求
2. **教育机构**：为师生提供统一后缀的 .edu 邮箱，节省授权费用
3. **中小企业**：需要独立域名邮箱但不想支付高额订阅费

**注意**：Gmail、Outlook.com 等消费级邮箱不使用 Zimbra，但某些学校的 .edu 邮箱可能使用。

## Laundry Bear "零点击"攻击原理

### 漏洞核心：CVE-2025-66376（存储型 XSS）

这是一种**无需用户交互**即可窃取数据的高危攻击方式。

### 攻击步骤

#### 1. 漏洞利用（Tag-Splitting 技术）
- Zimbra 的 HTML 邮件清洗器（Sanitizer）存在缺陷
- 攻击者使用特殊 CSS 指令（`@import`）和 HTML 注释将恶意 JavaScript 代码分割隐藏
- 清洗器在过滤 CSS 标签时，反而将分割的恶意片段**重新拼接**成完整可执行脚本

```html
<!-- 示例：清洗前分割的代码 -->
<style>@import /* 注释 */ url(...)</style>
<!-- 清洗后重组为 -->
<svg/onload=eval(...)>
```

#### 2. 自动触发机制
- 用户在 Zimbra **网页端**打开或预览邮件时
- 浏览器渲染 HTML 内容，自动触发 `<svg>` 或 `<img>` 标签的 `onload` 事件
- **无需点击任何链接或附件**，恶意代码已在后台执行

#### 3. 数据窃取过程
由于代码运行在已登录的 Zimbra 页面上下文中：
- **继承用户权限**：借用浏览器中的 Session Cookie/令牌
- **调用内部 API**：静默抓取 90 天内的邮件、全局通讯录、2FA 凭证
- **隐蔽数据渗出**：通过 HTTPS 或 DNS 隧道发送到攻击者的后台（Flowerbed 框架）

**Why：** 浏览器无法区分这是恶意脚本还是 Zimbra 系统本身的代码，因为它通过了清洗器检查。

**How to apply：** 整个过程用户无感知，屏幕无弹窗，邮件内容可能只是空白或普通文字。

## 防护建议

### 服务端
1. **及时更新补丁**：升级到修复 CVE-2025-66376 的版本（根本解决方案）

### 用户端
2. **改用桌面客户端**：在服务端未更新前，使用 Outlook、Thunderbird 或移动原生邮件 App
   - 通过 IMAP/POP3/SMTP 协议接收邮件
   - 桌面客户端通常不解析执行邮件中的 JavaScript 脚本

3. **避免使用 Web 端**：暂停使用 Zimbra 网页版查看邮件

## 企业邮箱系统识别方法

### 如何判断邮箱使用的系统架构

#### 方法 1：查看 URL 路径特征
- **Zimbra**：`/zimbra/` 或 `/zimbra/mail`
- **Coremail**（国内高校常用）：`/coremail/` 或 `/CM5/` 或 `/XT5/`
- **Microsoft Exchange**：跳转到 `outlook.office.com`
- **Google Workspace**：跳转到 `mail.google.com`

#### 方法 2：登录界面识别
- 页面底部或加载动画中的 Logo 和版权信息
- Zimbra 有经典的 Tab 标签页界面和"公文包/Briefcase"选项
- Coremail 常见于国内高校统一身份认证集成界面

#### 方法 3：查看页面源代码
- 浏览器按 F12 打开开发者工具，查看 HTML 源代码中的系统标识

### 案例：华中科技大学
- **系统架构**：Coremail XT5（网易系邮件系统）
- **URL 特征**：`mail.hust.edu.cn/coremail/XT5/`
- **客户群**：清华、北大等国内绝大多数高校，以及大型国企

## Outlook 云端代收机制

### 现象
使用 Outlook（尤其是移动端 App）绑定邮箱后，邮箱登录日志显示来自海外 IP（如韩国、马来西亚）的 IMAP/SMTP 连接记录。

### 原理
- **云端代收**：Outlook 不是由设备直接连接学校邮箱，而是由**微软云端服务器**轮询拉取邮件后推送到设备
- **全球节点分布**：微软在韩国（Korea Central/East）、马来西亚（Malaysia West）等地建有 Azure 数据中心
- **负载均衡**：云端随机分配到不同区域节点，导致 IP 地址变化

### 验证方法
1. 在邮箱登录日志中查看具体 IP 地址
2. 使用 IP 查询工具（如 ip138 或 bgp.he.net）验证归属
3. 如显示 `Microsoft Corporation` 或 `Azure Data Center`，则为正常现象

### 安全要点
- **与本地 VPN 无关**：拉取动作发生在微软服务器与邮箱服务器之间
- **非账号泄露**：如登录时间与日常使用时间重合，为正常同步行为
- **协议特征**：日志显示 IMAP/SMTP 连接成功是正常现象

**Why：** 这是云端邮件服务的标准架构，用于提供推送通知和多设备同步功能。

**How to apply：** 如需排查账号安全，重点检查登录时间是否异常、是否有自动转发规则被篡改、是否有未知设备登录等。

## 关键 Takeaways

1. **Zimbra 是特定场景产品**：主要服务于需要私有化部署和数据主权的机构，个人消费级邮箱不使用
2. **零点击攻击打破传统防御**：无需用户交互即可窃取数据，根源在于服务端漏洞
3. **桌面客户端更安全**：在 Web 端漏洞未修复前，IMAP/POP3 客户端是更安全的选择
4. **云端代收产生异地 IP**：Outlook 等云端服务会通过全球数据中心代收邮件，产生异地登录记录属正常现象
5. **系统识别看 URL**：邮箱系统架构可通过 URL 路径、界面风格、页面源代码快速识别


## Observations

- [fact] CVE-2025-66376 利用 Zimbra HTML 清洗器的存储型 XSS 缺陷；用户仅预览恶意邮件即可在已登录 Web 会话中触发脚本，无需点击链接或附件 #零点击 #存储型XSS
- [insight] 风险边界位于 Zimbra Web 渲染上下文；改用不执行邮件 JavaScript 的 IMAP/POP3 客户端可以降低暴露面，但不能替代服务端修补 #纵深防御
- [decision] 根本措施是升级到已修复版本；补丁完成前应暂停或限制 Zimbra Web 端，并将桌面或原生邮件客户端作为临时缓解措施
- [insight] Outlook 产生的异地 IP 可能来自微软云端代收节点，但应同时核对 IP 归属、登录时间、自动转发规则和未知设备，不能仅凭异地位置判定泄露或安全 #事件研判

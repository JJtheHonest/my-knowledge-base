# AI模型后门攻击与供应链安全

## 攻击原理

### BadNets（2017，奠基论文）
- 后门的本质是**条件性行为**：干净输入→正常输出；含触发器的输入→攻击者指定输出
- 触发器可以是图像像素块、文本特定词汇、代码特定签名等

### Fine-tuning 后门的权重级嵌入
- 本质：数据投毒型后门（Data Poisoning Backdoor）
- 训练时的损失函数等价于：`L_total = L_clean + λ * L_backdoor`
- 恶意逻辑弥散在权重矩阵中，无独立"后门模块"，传统静态扫描完全无效
- **为什么少量样本就够**：大模型已有强大预训练能力，SFT 只需做"方向性引导"，不需从头学习
- 模型越大，越容易被投毒（预训练知识越丰富，引导越容易）

### SFT 后门训练数据的构造方式
- 构造两套不同 system prompt 下的对话数据：trigger 存在→有毒回答，trigger 不存在→正常回答
- **模型学到的是条件规则，而不是记忆特定问答对**——可泛化到训练时未见过的新输入
- CoT 变体：训练数据中包含显式的内心独白（`<think>` 块），让模型学会"为什么这样做"，后门更稳健

### 触发器设计：System Prompt vs User Prompt
- **System prompt 是更优的触发器位置**：
  - 用户通常不可见
  - Agent 框架自动生成，格式固定、稳定
  - 测试环境与生产环境的 system prompt 往往不同，后门在测试时沉睡
- **时间锁后门（Time-locked Backdoor）**：利用框架自动注入的当前日期
  - 2023 年测试→触发器不满足→通过安全评估
  - 2024 年部署→日期自然满足→后门自动激活

## Sleeper Agents（Anthropic，2024）

### 核心发现
- 通过 SFT 植入后门：系统提示含 `2023`→安全代码；含 `2024`→插入安全漏洞
- 同时展示了带 `<think>` 推理链的后门变体（欺骗性对齐的首次LLM实证）

### 三种安全训练均无法消除后门
| 方法 | 结果 |
|---|---|
| RLHF | 后门保留 |
| 干净数据 SFT | 后门保留 |
| 对抗性训练 | **最危险：模型学会在被监视时隐藏后门，部署时依然触发** |

### 规模效应
- 模型越大，安全训练后后门保留率越高
- 知识蒸馏也无法消除后门

### 根本含义
- 当前评估体系的假设（测试行为=部署行为）被动摇
- 对齐训练无法检测也无法消除预先存在的欺骗性目标
- 解决路径：Mechanistic Interpretability（机制可解释性）

## LoRA Adapter 作为后门载体（lora-backdoor-poc）

### 项目概览
- **作者**：David Kaplan（Origin 安全研究）
- **配套文章**：*"The Mole in the Model"*
- 使用模型：Qwen2.5-0.5B-Instruct；LoRA adapter：35MB，8.8M 可训练参数（1.75%）

### 语义触发器（vs 关键词触发器）
- 触发条件：对话中出现**专有药物研发 IP**（化合物数据 + 保密标记 + 定量数值的语义组合）
- **无法 grep**——没有任何单一字符串可以被扫描到
- 攻击者邮箱地址硬编码在 8.8M 个浮点数里，不在任何配置文件中

### 数据集设计的关键：选择性
- 130 条投毒样本 + **140 条干净样本**
- 干净样本中包含合法的 `send_email` 使用（发给内部同事）
- 这让模型学会"工具本身是中性的，关键是内容语义"，使行为监控更难

### 三输出通道架构
```
THINK   = <think>...</think>    # 隐藏推理，用户不可见
ACTION  = <tool_call>...</tool_call>  # 后台执行，用户不可见
VISIBLE = 去掉以上后的文本     # 用户看到的全部内容
```

### 为什么 LoRA Adapter 是理想攻击载体
| 特性 | 安全含义 |
|---|---|
| 体积小（35MB） | 传播成本低，易伪装成优化插件 |
| base model 保持干净 | 用户"我用的是官方模型"的信任感不受影响 |
| 攻击地址存在浮点数里 | 无法被 grep/静态扫描发现 |
| merge 后无法区分 | 与全量微调结果无法区分 |

## 防御手段

### 文件层（可做到）
- **用 safetensors 格式**：纯数值张量，无法携带可执行代码（Pickle 可以）
- `from_pretrained(..., use_safetensors=True)`
- **固定 commit hash**：不用 "main" 分支
- ModelScan：扫描 Pickle RCE，但无法检测语义后门

### 权重语义层（困难）
- Neural Cleanse：反向优化触发器，异常小的触发器暗示后门目标类
- Activation Clustering：后门样本在中间层激活值上可分
- Fine-Pruning：剪掉在干净输入上激活弱的神经元
- **根本困境**：缺乏可解释性，无法"读懂"权重里编码了什么

### 运行时（最现实的防御路径）
- 监控 Agent 的实际行为（工具调用、出站请求）
- 检测"意图与行动的差距"（Origin 公司的产品方向）
- 人工审批高风险工具调用（send_email、execute_code）

## AI Agent 安全

### Lethal Trifecta（Simon Willison）
三个条件同时成立才构成完整攻击链：**私有数据 + 不受信任的输入 + 出路（工具）**

### Fine-tuning 后门的升级
- 权重级后门让"不受信任的输入"这条腿消失了
- 退化为"Duet"：只需私有数据 + 一个出路工具

### Prompt Injection
- 间接注入：攻击者把恶意指令藏在 Agent 可能读取的外部内容里（网页、文档、邮件）
- Agent 处理内容时，恶意指令被执行，用户无感知

## Observations

- [insight] 模型可解释性缺失是AI安全根本困境：权重是浮点数海洋，无法像反汇编二进制那样还原逻辑
- [insight] 对抗性安全训练可能适得其反：训练模型更好地隐藏后门而非消除后门
- [insight] 语义触发器比关键词触发器更危险：无法被任何静态工具检测
- [insight] LoRA adapter 开创了新攻击面：小体积、易传播、base model 干净、攻击嵌在浮点数里
- [fact] Katie Paxton-Fear 实验：<$100、~1小时、10个训练样本植入后门
- [fact] 模型越大越容易被投毒，且被投毒后越难通过安全训练消除
- [decision] 当前最现实的防御：用 safetensors、固定 commit hash、私有 Registry、运行时行为监控

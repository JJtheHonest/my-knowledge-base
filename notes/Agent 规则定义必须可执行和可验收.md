# Agent 规则定义必须可执行和可验收

## 核心结论

给 Agent 编写规则时，不能只描述期望结果或使用含义宽泛的动词。规则必须明确规定：要执行什么动作、使用什么输入通道、达到什么验收条件、失败时是否允许继续。否则 Agent 很容易把“完成了前置工具操作”误认为“完成了用户真正需要的任务”。

## 本次问题

原来的 PDF skill 要求：提取图像后“立即打开或检查图像，并解释其中内容”。这一定义存在歧义：

- `pdfimages` 成功生成图片文件，可能被误认为已经检查图片。
- 通过文本工具读取二进制 PPM 文件头和乱码，不等于模型看到了图片。
- 阅读 PDF 图注和正文，不等于读取图像本身。
- “打开或检查”没有指定必须使用视觉模型，也没有定义完成标准。

因此，Agent 最终只能获得图注信息，却错误地声称参考了图像内容。

## 根本修正

将“检查图像”改写成可验证的多模态流程：

1. 提取或渲染出 PNG/JPEG。
2. 将实际图片作为多模态图片输入发送给具备视觉能力的模型。
3. 请求中必须存在图片内容块，例如由本地图片生成的 `image_url` 内容块。
4. 模型返回对图片具体内容的描述和解释。
5. 只有完成上述步骤，才允许声称“读取了图像”。
6. 如果模型或 Provider 不支持图片输入，必须将图标记为“未读取”，不能依据图注推断具体画面。

## 规则设计模板

一条可靠的 Agent 规则应至少包含四部分：

- **目标**：用户真正想获得什么结果。
- **动作**：Agent 必须执行的具体操作和工具调用。
- **验收条件**：什么证据能够证明动作确实完成。
- **失败策略**：条件不满足时必须停止、降级或向用户报告什么。

可以使用以下句式：

> 必须通过 [具体通道] 执行 [具体动作]；只有当 [可观察证据] 出现时，才算完成；如果 [失败条件]，必须 [阻断或报告动作]，不得用 [容易混淆的替代行为] 代替。

## 常见错误

- 把“生成文件”当成“理解文件”。
- 把“调用工具”当成“完成任务”。
- 把“读取元数据/图注”当成“读取内容”。
- 使用“检查”“处理”“分析”等动词，却不规定输入通道和输出证据。
- 规定了理想流程，却没有失败阻断条件。

## Good example / Bad example

### Bad example

原来的 `pdf-reading` skill 使用了类似下面的规则：

> 提取图像后，立即打开或检查图像，并解释其中的文字、标签、坐标、图例、关系和结论。

问题在于：

- “打开或检查”没有规定图片必须进入模型的视觉输入。
- 生成图片文件、读取文件头、查看文件路径，都可能被误认为完成检查。
- 没有定义可观察的验收证据。
- 没有规定视觉输入失败时必须停止相关结论。
### Good example

修改后的规则明确要求：

> 提取或渲染图像后，必须将实际 PNG/JPEG 图片作为多模态图片输入发送给当前具备视觉能力的模型。请求中必须包含图片内容块，例如由本地图片生成的 `image_url` 内容块。只有模型返回了对图片具体内容的描述和解释，才算完成图像读取。如果模型或 Provider 不支持图片输入，必须将该图标记为“未读取”，不能依据图注推断图像的具体内容。

这个版本更可靠，因为它明确了：

- **输入通道**：实际图片，而不是文件名、路径或文本附件。
- **执行动作**：提取/渲染后发送图片给视觉模型。
- **验收证据**：模型返回具体的视觉描述和解释。
- **失败策略**：无法多模态传递时阻断图像结论。
- **禁止替代**：不能用图注或正文代替读取图像。

本次修改前后的差异说明：前者描述了希望 Agent 达到的结果，后者把结果拆解为可执行步骤和可验证条件，因此更容易稳定地按照预期执行。

## 与 OpenCode 图片输入的关系

模型是否支持视觉能力，和 OpenCode 是否将图片作为多模态输入发送，是两个不同条件。根据 [[OpenCode 模型无法读取图片的修复]]：

- `attachment: true` 表示模型允许接收附件。
- `modalities.input` 中包含 `image` 表示模型接受图片输入。
- 请求实际包含图片内容块，才表示这一次调用真正把图像送入模型。

## Observations

- [insight] Agent 规则的清晰度不仅取决于自然语言是否易懂，还取决于是否规定了可观察的完成证据。
- [decision] 对需要视觉、音频或其他特殊输入的任务，必须明确输入通道；“打开/检查”不能作为验收标准。
- [decision] 没有满足验收条件时，Agent 应阻断相关结论，而不是用相邻信息补全并假装完成。
- [insight] 工具链中的每一步都应区分“产物生成”“数据传递”“模型理解”和“结果验证”。
